# راه‌اندازی سرور Minecraft در GitHub Codespaces با Playit.gg

این مخزن یک نصب‌کننده تعاملی برای ساخت سرور **Minecraft Java Edition** در محیط Ubuntu-based GitHub Codespaces فراهم می‌کند. امکان نصب سرور Vanilla یا Paper، انتخاب نسخه بازی، تعیین RAM و تعداد بازیکنان، بکاپ دنیا، Restart پس از Crash و اتصال عمومی با Playit.gg وجود دارد.

> **محدودیت مهم:** GitHub Codespaces سرویس میزبانی دائمی بازی نیست. Codespace ممکن است پس از مدتی بی‌کاری متوقف شود و سهمیه رایگان/هزینه به پلن، نوع ماشین و تنظیمات حساب بستگی دارد. هیچ‌یک از اسکریپت‌های این مخزن نمی‌توانند Codespace متوقف‌شده را دوباره روشن کنند. برای میزبانی ۲۴/۷ از VPS یا میزبان اختصاصی Minecraft استفاده کنید.

## امکانات

- انتخاب Vanilla یا Paper در زمان نصب
- دریافت فهرست نسخه‌های رسمی Minecraft از Mojang و انتخاب نسخه پایدار یا نسخه دلخواه موجود
- تشخیص نسخه Java موردنیاز از metadata همان نسخه و نصب بسته متناظر در مخازن سیستم
- بررسی خطاهای دانلود و معتبر بودن فایل سرور
- تعیین RAM، حداکثر بازیکنان و View Distance
- فایل اجرای عادی و فایل اجرای مجدد پس از Crash
- بکاپ فشرده از پوشه‌های دنیا و حذف خودکار بکاپ‌های قدیمی
- زمان‌بندی بکاپ با cron در محیط‌هایی که cron فعال است
- نصب و اجرای Playit Agent
- نصب پلاگین‌های Paper از لینک مستقیم HTTPS فایل JAR
- راهنمای فارسی

## پیش‌نیازها

1. حساب GitHub با دسترسی GitHub Codespaces.
2. Codespace مبتنی بر Ubuntu/Debian که `sudo` و `apt-get` داشته باشد.
3. اتصال اینترنت برای دریافت Java، فایل سرور و در صورت انتخاب Playit.
4. حساب Playit.gg برای آدرس عمومی (اختیاری).
5. منابع کافی برای نسخه Minecraft و تعداد بازیکنان موردنظر.

## شروع سریع

### ۱) ساخت Codespace

1. مخزن را در GitHub باز کنید.
2. روی **Code** و سپس **Codespaces** بزنید.
3. گزینه **Create codespace on main** را انتخاب کنید.
4. پس از آماده‌شدن محیط، ترمینال VS Code را باز کنید.

اگر از Fork استفاده می‌کنید، مطمئن شوید شاخه‌ای که Codespace از آن ساخته شده همین نسخه اصلاح‌شده است.

### ۲) اجرای نصب‌کننده

در ترمینال، از ریشه مخزن اجرا کنید:

```bash
chmod +x setup_mc_server.sh
./setup_mc_server.sh
```

نصب‌کننده به‌ترتیب از شما این موارد را می‌پرسد:

- نوع سرور: `1` برای Vanilla یا `2` برای Paper
- نسخه Minecraft؛ با خالی گذاشتن، آخرین نسخه پایدار رسمی انتخاب می‌شود
- نسخه Paper؛ در حالت Paper به‌طور پیش‌فرض همان نسخه Minecraft است
- RAM جاوا بر حسب GB
- حداکثر تعداد بازیکنان
- View Distance
- نصب یا عدم نصب Playit.gg

نسخه Minecraft باید در فهرست رسمی Mojang وجود داشته باشد. برای Paper، همان نسخه باید در API رسمی Paper نیز در دسترس باشد. اگر نسخه Java لازم در مخازن سیستم‌عامل موجود نباشد، نصب‌کننده با پیام خطا متوقف می‌شود؛ در این حالت از یک Codespace/Ubuntu جدیدتر یا محیطی با بسته Java مناسب استفاده کنید.

### ۳) پذیرش EULA

نصب‌کننده عمداً EULA را خودکار نمی‌پذیرد. ابتدا متن رسمی را بخوانید:

https://aka.ms/MinecraftEULA

اگر با آن موافق هستید:

```bash
cd ~/minecraft-server
nano eula.txt
```

مقدار `eula=false` را به `eula=true` تغییر دهید و ذخیره کنید (`Ctrl+O`، Enter، سپس `Ctrl+X`). بدون پذیرش EULA سرور اجرا نمی‌شود.

### ۴) اجرای سرور

اجرای عادی:

```bash
cd ~/minecraft-server
./start.sh
```

اجرای همراه با تلاش مجدد پس از Crash:

```bash
./start_auto.sh
```

`start_auto.sh` پس از خروج غیرعادی سرور، ۱۰ ثانیه صبر می‌کند و دوباره اجرا می‌کند. اگر سرور با خروج عادی متوقف شود (برای مثال دستور `stop`)، حلقه Restart پایان می‌یابد. برای توقف حلقه، `Ctrl+C` بزنید.

> Restart فقط وقتی Codespace و ترمینال/پردازش فعال باشند کار می‌کند. این اسکریپت نمی‌تواند Codespace خوابیده یا متوقف‌شده را بیدار کند.

## اتصال بازیکنان از اینترنت با Playit.gg

1. در https://playit.gg حساب بسازید یا وارد حساب خود شوید.
2. در ترمینال جداگانه Codespace اجرا کنید:

```bash
cd ~/minecraft-server
./start_tunnel.sh
```

3. در اولین اجرا، دستورالعمل اتصال Agent به حساب Playit را دنبال کنید.
4. در پنل Playit یک تونل Minecraft Java با مقصد محلی `25565` بسازید، اگر به‌صورت خودکار ساخته نشده است.
5. آدرس عمومی و پورت نمایش‌داده‌شده در Playit را به بازیکنان بدهید.

سرور Minecraft و Playit باید هم‌زمان اجرا باشند؛ برای هرکدام یک ترمینال جداگانه باز کنید. اگر Codespace متوقف شود، تونل و سرور نیز قطع می‌شوند.

اگر هنگام نصب Playit از گزینه نصب صرف‌نظر کردید، مستندات رسمی را ببینید:
https://playit.gg/support/

## تنظیمات

فایل تنظیمات بازی:

```bash
nano ~/minecraft-server/server.properties
```

گزینه‌های پرکاربرد:

| گزینه | توضیح |
|---|---|
| `max-players` | حداکثر تعداد بازیکنان |
| `gamemode` | حالت بازی مانند `survival` یا `creative` |
| `difficulty` | درجه سختی مانند `easy`، `normal` یا `hard` |
| `pvp` | فعال یا غیرفعال بودن PvP |
| `white-list` | فعال‌سازی فهرست مجاز |
| `view-distance` | فاصله نمایش دنیا |
| `simulation-distance` | فاصله شبیه‌سازی دنیا |
| `motd` | پیام سرور در فهرست Multiplayer |

برای فعال‌کردن Whitelist مقدار `white-list=true` را قرار دهید. سپس در کنسول سرور:

```text
whitelist add PlayerName
```

برای ادمین‌کردن بازیکن:

```text
op PlayerName
```

پس از تغییر `server.properties` معمولاً باید سرور را متوقف و دوباره اجرا کنید.

RAM در فایل زیر ذخیره می‌شود:

```bash
nano ~/minecraft-server/server.env
```

مقدار `RAM_GB` را تغییر دهید. RAM اختصاص‌یافته نباید از حافظه قابل‌استفاده Codespace بیشتر شود؛ برای سیستم‌عامل و ابزارهای دیگر هم حافظه خالی بگذارید.

## بکاپ دنیا

بکاپ دستی:

```bash
cd ~/minecraft-server
./backup.sh
```

فایل‌های بکاپ به‌صورت فشرده در `~/minecraft-backups` قرار می‌گیرند. اسکریپت به‌طور پیش‌فرض بکاپ‌های قدیمی‌تر از ۷ روز را پاک می‌کند. برای تغییر مدت نگهداری:

```bash
BACKUP_KEEP_DAYS=14 ./backup.sh
```

زمان‌بندی هر ۶ ساعت:

```bash
./install_backup_cron.sh 6
```

می‌توانید عدد ۱ تا ۲۳ را به‌عنوان فاصله ساعت وارد کنید. برای حذف زمان‌بندی، فهرست cron کاربر را با `crontab -e` و خط مربوط به `backup.sh` را پاک کنید.

**نکته سازگاری بکاپ:** بهترین روش، اجرای `save-all` در کنسول و سپس بکاپ‌گیری در زمان توقف سرور است. بکاپ زمان اجرای بازی ممکن است در صورت نوشتن هم‌زمان فایل‌های دنیا کاملاً سازگار نباشد. همچنین cron در همه Codespaces فعال یا پایدار نیست و زمان‌بندی تا وقتی محیط اجرا و cron فعال باشند کار می‌کند؛ بکاپ را به فضای دیگری منتقل کنید تا در صورت حذف Codespace از بین نرود.

## Paper و پلاگین‌ها

Paper برای اجرای پلاگین‌های سازگار با Bukkit/Spigot/Paper است؛ مودهای Forge/Fabric را اجرا نمی‌کند.

1. هنگام نصب، نوع سرور `2` یعنی Paper را انتخاب کنید.
2. پس از نصب، فایل زیر را باز کنید:

```bash
nano ~/minecraft-server/plugins.txt
```

3. در هر خط، URL مستقیم و HTTPS فایل `.jar` یک پلاگین معتبر را قرار دهید. خط‌های شروع‌شده با `#` نادیده گرفته می‌شوند.
4. نصب‌کننده پلاگین را اجرا کنید:

```bash
cd ~/minecraft-server
./install_plugins.sh
```

5. سرور را Restart کنید.

فقط از منابع معتبر و پلاگین‌های متناسب با نسخه Paper خود استفاده کنید. فایل‌های JAR کد اجرایی هستند؛ پیش از نصب، ناشر و محتوای آن‌ها را بررسی کنید. لینک صفحه وب یا لینک دانلودی که به فایل JAR مستقیم ختم نمی‌شود پذیرفته نخواهد شد.

## عیب‌یابی

**خطای نسخه Java**

```bash
java -version
```

نسخه نصب‌شده باید با نسخه انتخاب‌شده Minecraft سازگار باشد. اگر بسته Java در مخازن Ubuntu موجود نیست، از Codespace جدیدتر استفاده کنید.

**فایل server.jar دانلود نشده یا ناقص است**

اتصال اینترنت و پیام curl را بررسی کنید؛ سپس نصب‌کننده را دوباره اجرا کنید. فایل قبلی در صورت وجود با نام زمان‌دار نگهداری می‌شود.

**سرور اجرا نمی‌شود**

- مطمئن شوید `eula=true` را فقط پس از پذیرش EULA تنظیم کرده‌اید.
- با `java -version` نسخه Java را بررسی کنید.
- RAM را در `server.env` کاهش دهید.
- خروجی ترمینال را بررسی کنید.

**دوستان نمی‌توانند وصل شوند**

- مطمئن شوید سرور در حال اجراست و پیام `Done` را نشان داده است.
- Playit Agent باید در ترمینال دوم فعال باشد.
- مقصد تونل باید پورت TCP `25565` باشد.
- آدرس و پورت عمومی Playit را دقیقاً وارد کنید.

**Codespace متوقف شده است**

از صفحه Codespaces در GitHub آن را دوباره Start کنید. پس از بازشدن ترمینال، سرور و تونل را مجدداً اجرا کنید.

## نکات امنیتی و نگهداری

- توکن‌ها، اطلاعات ورود یا فایل‌های حساس Playit را در Git قرار ندهید.
- پلاگین‌ها را فقط از منابع مورد اعتماد بگیرید.
- برای سرور عمومی Whitelist و دسترسی‌های مدیریتی را با دقت تنظیم کنید.
- از دنیا بکاپ بگیرید و نسخه‌ای خارج از Codespace نگهداری کنید.
- اجرای Minecraft در Codespaces ممکن است با شرایط استفاده، محدودیت منابع و سهمیه حساب GitHub محدود شود.
